# Repository remotes qualification

These acceptance rules belong to SRV-GOV-001. Native source, host adoption and
release evidence remain independent.

The [native account transport intake](../../../records/2026-11-15-remotes-native-account-main-intake.md)
retains concurrent Lapis Sync policy separately from Git backup synchronization,
with duplicate-manifest and bounded-chapter regression evidence.

Synchronization qualification starts with the admitted opt-out command's missing-
capability regression. Prove explicit opt-in, idle work count, detach survival,
successful close drain and refused-close continuity. Use native merge/conflict
and guarded apply receipts before publication; restart of an uncertain apply
must wait for an explicit exact-request retry or keep-current action. Conflict
inspection/resolution stays on the existing production inspector. Status reads
must not wait behind transfer turns. Actual HTTPS/SSH two-vault convergence,
dirty-editor guards, rejection and lost publication responses remain required.

Shared remote selection qualification covers private-root admission, independent
backup/original state, explicit manual defaults, exact revisions and credential
reference validation. Source selection tests do not qualify transfer, scheduling,
secret custody or host HTTP/Tauri admission.

Forge secret-custody qualification retains the existing repository token format
and separates account metadata from encrypted credential JSON. Source tests
prove full account/owner binding and restart/replace/forget behavior; they do
not qualify sign-in delivery, admitted HTTP routes or real forge transport.

Native remotes intake records the checked jj-store PR tree and its identical
merged source tree separately. Portable Cargo pins and configure checks select
the merged revision. Adapter/cold-key tests qualify injected encrypted custody;
they do not qualify host manager startup, HTTP/Tauri admission or application
publication.

Remote work-lifetime qualification distinguishes accepted native completion from
response delivery. Test cancelled waiters, detached clients, subsequent clients,
restart persistence and vault closure using the real Core runtime. This source
boundary does not enable HTTP/Tauri adapters or qualify network transfers.

Shared working-copy qualification compares physical unsnapshotted file counts
with unchanged native operation heads and checkout bytes. It reuses jj-store's
owned observer rather than copying its scanner or diff algorithm. Unsupported
no-original cases and stale client admission retain explicit refusal evidence.

Original settings discovery qualifies passive remote inventory, credential URL
redaction and unchanged original configuration/checkout metadata. Reader grants
must remain immutable through the owning jj-store read-only constructor. Shared
Protocol generation and existing accepted-work lifecycle tests remain required;
these source checks do not qualify guarded save or any network transfer.

Guarded original-save qualification includes a real native configuration change,
stale external config refusal, preservation of unrelated remotes and checkout
bytes, cross-process private-lock ordering, failure rollback of private selection,
credential admission before Git writes, and host SSH setup with locked token
storage. Native source, transfer and cold application gates remain distinct.

Manual original-transfer qualification uses real Core services and disposable
Git/SSH endpoints independently from mocked UI and cold host acceptance. Prove
review persistence and exact single-branch publication, unchanged unsnapshotted
files/checkout bytes, status after metadata-only fetch, consumed-review refusal,
and lost-response restart recovery without a second receive. Credential-ID
preflight and cross-process selection locking must be tested before secret
resolution; cancelled waiters retain accepted work. An SDK defect is fixed and
qualified upstream before permanent host intake. A temporary unmerged source
qualification pin must retain its PR and checked revision and become a merged
pin before delivery. Native transfer flags do not enable HTTP/Tauri routes.

Backup orchestration qualification uses real transport with the actual capture
worker and a separate standby runtime. Retain the first missing-capability
failure; prove immutable checkpoint review across later capture, no publication
from saving/capture, independent target journals and restart recovery without a
second receive. Shared private-record storage changes rerun both original and
backup transport scenarios. Native library, application host and release
qualification remain separate.

Credential mutation qualification uses an installation process fence and a
durable secret-free observation epoch. Prove cross-vault stale refusals, failed
or lost provider responses, scope-preserving replacement, epoch rollback refusal
and accepted completion after waiter cancellation/detach. Retained publication
credentials remain protected across vaults and source-observation changes until
native terminal recovery/local stop retires the hold. Policy fixtures and local
prepared receipts do not qualify actual host custody or network authentication;
rerun both real transport scenarios after shared journal/terminal cleanup changes.

Native provider composition qualifies shared Core account/scope/device-flow
policy separately from host custody. Exercise raw-token lifecycle, SDK-backed
GitHub/Enterprise/Forgejo replacement, cross-method and cross-endpoint refusal,
locked inventories, sign-in polling/expiry/cancellation and secret-free public
state. The encrypted Server adapter additionally proves owner isolation and
cold store reopening with the correct, absent and wrong keys. Both adapters
retain authenticated host-route and real transport gates; provider fixtures
cannot establish live forge sign-in or cold application acceptance.

No-original status qualification uses an existing native checkpoint and the
operation-pinned native diff response. Test both text and binary changes with a
live capture lease held, later unrecorded files, unchanged native operations and
no vault metadata initialization. An invalid original must refuse instead of
falling back to backup. Native hunks supply statistics; application code must
not implement a scanner or diff algorithm. Missing/complex observations stay
unavailable, and source status does not qualify either host composition.

Host route/startup qualification exercises actual HTTP authentication and private
encrypted storage. Retain the initial missing-route regression, then test vault/
generation/principal isolation, protocol/origin/CSRF, bounded secret input and
retired clients. Cold host reconstruction must retain private identity, selection
and opaque credentials across correct, absent and incorrect keys. Key/trust and
identity location/symlink failures must refuse before a host is exposed. Actual
HTTP transport/custody evidence does not substitute for browser UI or native
HTTPS/SSH acceptance, automatic scheduling or either application release gate.

Browser transport qualification records the initial missing-port failures, then
proves immutable client/vault/generation scoping, exact reviewed command bodies,
late-response fencing and no replay after detach. Preserve raw working-copy JSON
without parsing native identities at the transport boundary. Client units alone
do not qualify the production browser shell or network authentication.

Server remote startup and authenticated-route qualification follows the
[repository rules](remotes.md) under SRV-GOV-001. Actual HTTP custody
and source-level transport evidence remain distinct from browser adoption,
Desktop integration, native automatic synchronization and release acceptance.

Admitted remote browser ports qualify exact client/vault/generation routing,
late-delivery fencing and no publication replay independently from native custody.
Their unit evidence does not enable or qualify the application settings surface.

Native backup synchronization follows the same [repository qualification rules](remotes.md).
Keep its source orchestration, passive authenticated status, explicit recovery,
actual SSH/HTTPS transport and cold host UI evidence distinct. The scheduler's
idle lifetime must not hold a vault work lease or a renderer dependency.
